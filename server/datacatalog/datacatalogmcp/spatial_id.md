# 空間ID（Spatial ID）とは

空間IDは、地球上の3次元空間を直方体（ボクセル）に分割し、一意の識別子を割り当てる規格です。デジタル庁・経済産業省・国土交通省が策定を進めており、自動運転車やドローンなどの自律移動モビリティの運行に必要なデジタルツイン構築に活用されています。

## フォーマット

空間IDは **`{z}/{f}/{x}/{y}`** 形式で表現されます。

| 要素 | 説明 | 例 |
|------|------|-----|
| **z** | ズームレベル（0〜25+） | 15 |
| **f** | fインデックス（鉛直方向） | 0 |
| **x** | xインデックス（東西方向） | 29134 |
| **y** | yインデックス（南北方向） | 12950 |

**例**: `15/0/29134/12950`

## ズームレベルと解像度

ズームレベルが1増えると、空間ボクセルが8分割（水平4分割×垂直2分割）されます。

| ズームレベル | 水平解像度（赤道付近） | 垂直解像度 | 用途例 |
|-------------|----------------------|-----------|-------|
| 0 | 約40,000km | 約33,554km | 地球全体 |
| 10 | 約152m | 約32km | 広域 |
| 15 | 約4.8m | 約1km | 建物群 |
| 18 | 約0.6m | 約128m | 建物単体 |
| 20 | 約0.15m | 約32m | 詳細構造 |
| 25 | 約1.2cm | 約1m | 最高精度 |

※ 水平解像度は緯度により変化します（日本周辺では赤道の約80%程度）

## 座標計算式

経緯度・標高から空間IDを計算する式:

```
n = 2^z
H = 2^25 メートル (≒33,554km)

f = floor(n × h / H)           # h: 標高(m)
x = floor(n × (lng + 180) / 360)
y = floor(n × (1 - log(tan(lat_rad) + 1/cos(lat_rad)) / π) / 2)
```

- x, y は標準的なWebメルカトル（Slippy Map Tilenames）と同じ
- 高さの基準は標高0m（東京湾平均海面）
- 測地系: JGD2011 または WGS84

## 鉛直方向の範囲

- 範囲: ±33,554,432m（地表からの上空・地下）
- f = 0 は標高0m付近を含む層
- f が正の値は上空、負の値は地下

## PLATEAUでの使い方

1. **`plateau_get_citygml_files`** で空間IDを指定してCityGMLファイルを検索:
   ```
   condition: "s:15/0/29134/12950"
   ```

2. **`plateau_citygml_get_features`** で空間IDに交差する地物を取得:
   ```
   spatial_ids: ["15/0/29134/12950", "15/0/29134/12951"]
   ```

**重要**: 空間ID検索では**LOD1Solidのジオメトリのみ**が使用されます。LODによる検索結果の差異はありません。

## PLATEAUデータの特性と推奨設定

### 地物タイプ別の推奨ズームレベル

| 地物タイプ | コード | 推奨ズーム | 理由 |
|-----------|--------|-----------|------|
| 建築物 | bldg | **17〜19** | 建物単位で検索するため高解像度が必要 |
| 道路 | tran | 15〜17 | 道路ネットワーク全体を俯瞰 |
| 土地利用 | luse | 14〜16 | 広域の土地利用パターン |
| 洪水浸水 | fld | 13〜15 | 流域単位の広域データ |
| 地形 | dem | 14〜16 | 地形メッシュ単位 |

### fインデックス（高さ方向）の使い方

- **f=0**: 地表面付近。**ほとんどのケースでこれを使用**
- **f=1〜3**: 高層建築物（50m〜200m程度）
- **f=-1**: 地下構造物

**推奨**: 建築物検索では`f=0`から始めて、必要に応じて`f=1,2`も追加すると効率的。

### PLATEAUデータの空間分布（重要）

PLATEAUデータは**全国一律ではなく**、以下の特性があります：

1. **整備済み都市のみ**: 全国約200都市が対象（2024年時点）
2. **年度差異**: 2020〜2024年度で順次整備
3. **メッシュ単位**: 3次メッシュ（約1km四方）ごとにファイル分割

※ データ自体にはLODの違い（LOD1/LOD2/LOD3）がありますが、**空間ID検索ではLOD1Solidのジオメトリのみ**が使用されるため、検索結果に差異は生じません。

### トラブルシューティング

**空の結果が返る場合:**

1. **ズームレベルを確認**: 建築物は`z=17〜19`を推奨。低すぎると該当なしになりやすい
2. **fインデックスを0に**: `f=1`などでは地上の建物が取得できないことがある
3. **対象都市の確認**: `plateau_search_areas`で整備状況を確認
4. **メッシュコード直接指定**: `plateau_get_citygml_files`の`m:メッシュコード`条件を試す

**例: 千代田区（東京駅周辺）の建築物を検索する場合**

```
# Step 1: CityGMLファイルを取得
plateau_get_citygml_files(condition="m:53394621", feature_types=["bldg"])

# Step 2: 空間IDで建物IDを取得（z=18, f=0を使用）
plateau_citygml_get_features(url="...", spatial_ids=["18/0/232848/103220"])

# Step 3: 建物属性を取得
plateau_citygml_get_attributes(url="...", building_ids=["bldg_xxx"])
```
